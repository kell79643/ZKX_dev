# 高精度 CPU 参考最终深度验证报告

## 一、最终判断

高精度 CPU 相关工作已经达到当前项目的停止条件。2026-07-17 在中科芯 ZQ500
`gpu_02` 环境完成最终复跑，测试源提交为
`da63935183f1b4c2bdc0ecd45c42e1418b498689`：

- 7 个代表算子；
- 20 个 baseline/long/sensitive/Task 场景；
- FP32、FP16 共 40 条精度记录，40/40 通过；
- Task1 两种 dtype 共 2 条峰值业务记录，2/2 通过；
- 实现一致性、高精度诊断和高精度基准 mismatch 均为 0。

本轮不追求给全部 53 个算子建立高精度公式，而是围绕会影响项目精度选择的风险开展深度
验证，并把结果传播到实际 Task1 链路。

## 二、三类字段实际代表什么

交付结论只有两个 CPU 比较对象：

| 比较 | 公式 | 回答的问题 |
|---|---|---|
| 实现一致性 | GPU(dtype X) − typed CPU(dtype X) | GPU 是否正确实现当前 dtype 契约 |
| 高精度基准总误差 | GPU(dtype X) − long double(共同原始高精度输入) | 采用该 dtype 后总体损失多少 |

`diagnostic_compute_*` 并非第三个 CPU reference。它只是让同一个 `long double` 公式
读取已经编码为 FP32/FP16 的输入，帮助区分“输入表示损失”和“后续计算/输出损失”。

## 三、为何这些场景对当前项目有用

| 风险 | 覆盖路径 | 对项目的帮助 |
|---|---|---|
| 长序列乘加 | correlate、FIR、脉冲压缩 | 观察舍入是否随长度积累 |
| 递归状态传播 | sosfilt | 发现单一短输入看不到的误差放大 |
| 三角函数与归约 | lombscargle、pulse_doppler | 检查频谱/多普勒峰值是否受精度影响 |
| 插值、抽取与边界 | upfirdn | 检查相位和零边界的数值稳定性 |
| 任务链传播 | Task1 脉冲压缩→多普勒 | 判断算子误差是否改变目标峰值 |

这使高精度基准从“额外算子测试”变成 dtype 决策证据：同 dtype CPU/GPU 即使完全一致，
也不能证明 FP16 相对高精度输入没有损失。

## 四、结果与精度决策

### 4.1 最大观测误差

| 路径 | FP32 高精度基准 max abs | FP16 高精度基准 max abs |
|---|---:|---:|
| correlate | `5.869574e-6` | `1.451140e-2` |
| sosfilt | `1.096570e-6` | `4.285294e-3` |
| lombscargle | `2.841535e-7` | `2.569287e-3` |
| firfilter | `1.928313e-7` | `8.936972e-4` |
| upfirdn | `7.264146e-8` | `5.321968e-4` |
| pulse_compression | `1.640548e-6` | `1.152532e-3` |
| pulse_doppler | `1.489740e-6` | `1.192724e-3` |
| Task1 两算子链 | `2.608110e-5` | `4.111133e-3` |

FP32 在算子场景中保持约 `6e-6` 以内，Task1 链为 `2.61e-5`。FP16 对场景更敏感，
在相关敏感场景达到 `1.45e-2`。typed CPU/GPU 仍保持一致，因此增长主要是 FP16 表示
与有限精度造成的，而不是 GPU 偏离该 dtype 的参考算法。

最大相对误差在参考值接近零时可能被放大，不能单独判错；本报告同时使用最大绝对误差、
RMSE、组合容差和业务指标。

### 4.2 Task1 传播

固定场景使用 32×256 数据、脉冲长度 64、delay 80、Doppler bin 5、PRF 8000 和固定噪声。
FP32/FP16 的 GPU、typed CPU、高精度参考均输出 range bin 80、Doppler bin 5。

这证明当前单目标场景峰值位置稳定。它不证明 FP16 在弱目标、多目标、近阈值检测或更长
积累场景普遍安全，因此正式 Task1 保持 FP32。

### 4.3 Task2 边界

Task2 直接相关的 `firfilter`（实际长度风险）与 `correlate` 已覆盖 baseline、long、
sensitive。Task2 正式流程仍为 FP32；在没有计划切换低精度的前提下，再复制一条完整
Task2 `long double` 任务链不会改变当前决策，因此本阶段不做机械扩展。

## 五、停止与重启条件

当前阶段停止继续扩算子。只有出现以下情况才重启：

- Task1/Task2 某步骤准备正式切换 FP16 或其他低精度；
- 新输入规模、动态范围或业务阈值超出本轮覆盖；
- 线上/测试发现峰值、SNR、检测率或递归稳定性异常；
- 整数路径已定义 scale、zero-point、反量化、舍入与饱和/环绕语义；
- 正式算法实现发生会改变数值路径的修改。
