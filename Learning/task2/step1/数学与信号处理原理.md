# Task2 Step1 数学与信号处理原理

## 1. 定位

Step1 用四种附件波形构造一个目标、三种确定性干扰和均匀伪随机噪声。版本为 clean
`f6559d058edddaad5909cc67f992bb731d47127e`，源码为
`ZKX/Task2/task2_gpu_cpu/step1/step1.cu`。

联动：[chirp](../../operators/waveforms/chirp/数学物理原理.md)、
[gausspulse](../../operators/waveforms/gausspulse/数学物理原理.md)、
[sawtooth](../../operators/waveforms/sawtooth/数学物理原理.md)、
[square](../../operators/waveforms/square/数学物理原理.md)。

## 2. 四种波形与叠加

目标 chirp 的一般形式是 $c(t)=\cos(2\pi\int_0^t f(u)du+\phi)$，任务调用线性 sweep
`20→70 Hz`。高斯调制脉冲是高斯包络乘载波；任务用中心偏移后的时间 `t-0.45`、载频
170 Hz、带宽参数 0.20。锯齿和方波分别使用 190 Hz、125 Hz 相位，并设置 width/duty
0.65/0.35。

叠加公式：

$$
y[n]=a_tc[n-d]+(a_gg[n]+a_ss[n]+a_qq[n])+w[n].
$$

任务分别保存 target/interference/noise，便于验证各分量，而不是只保存总和。

## 3. 延迟与噪声

整数延迟通过 `index>=delay ? chirp[index-delay] : 0` 实现，不做分数延迟。噪声整数 hash 与
Task1 同族，映射到近似 $[-a_w,a_w]$，不是高斯分布。

## 4. dtype 工程差异

`chirp`、`gausspulse` 输出 FP32；当前 `sawtooth`、`square` API 输出 FP64，任务先 D2H，
在 Host 显式窄化为 FP32，再 H2D 给混合 kernel。这是当前类型契约带来的数据搬运，不是波形
数学要求。代码证据为 `step1.cu:74-107`。

## 5. 自检问题与答案

### 问题 1

任务是否满足“至少三种波形”？

### 答案 1

满足且使用四种正式算子：chirp、gausspulse、sawtooth、square，见 `step1.cu:78-92`。

### 问题 2

为什么不能把三种干扰权重解释为概率？

### 答案 2

它们是线性幅度系数，代码没有要求和为 1，也没有随机选择波形。
