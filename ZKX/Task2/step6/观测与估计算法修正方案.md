## Step6 错位理解修正

赛题第 6 步要求"使用 kalmanfilter 进行参数估计"。当前实现把"多尺度质心序列"直接送入标量 Kalman 的 predict-update 循环，形式上满足条款，但在状态空间建模与参数语义上存在以下错位。需先在建模层面对齐，后续修改 1-6 才能在统一框架下成立。

### 错位点 1：估计参数不明确

代码与配置都未显式声明 Step6 估计的"参数"是什么。从 `state.truth` 与 `state.estimate` 的比较关系反推，实际估计对象是**归一化目标回波到达位置**：

$$\theta = \frac{\text{target\_delay\_samples} + 0.5(N-1) + \tau_{\text{filter}} + \tau_{\text{spline}}}{N-1} \in [0, 1]$$

其中 $N$ 为 `feature_bundle.size()`，$\tau_{\text{filter}} = (\text{filter\_taps}-1)/2$，$\tau_{\text{spline}} = (9-1)/2 = 4$。$\theta$ 的物理含义是目标回波在归一化坐标下的位置。后续所有修改都应在代码注释与文档中显式声明这一估计对象，避免被误读为"时延样本数""SNR"或"目标幅度"。

### 错位点 2：状态空间模型语义错位

`observations_from_feature_point` 按 `radius=1..K` 生成观测序列，每个观测是"以 anchor 为中心、宽度为 $2r+1$ 的窗口内加权质心"。观测索引 $k$ 实际是"窗口宽度参数"，不是物理时间或递推步数。直接送入 `kalman_predict_update_scalar_sequence_device` 后，从外部看像"动态系统状态跟踪"，实质是"对同一静态参数 $\theta$ 的多次带噪观测融合"。

正确的建模应是**静态参数的序贯估计**：

- 状态方程：$\theta_k = \theta_{k-1}$（参数恒定，对应 `F=1`）
- 观测方程：$z_k = \theta + v_k$（直接观测，对应 `H=1`），$v_k$ 是窗口 $k$ 的偏置噪声

这是 Kalman 滤波器作为"序贯参数估计器"（sequential parameter estimator）的标准用法，与"目标动态跟踪"在数学形式上等价，但物理含义不同。明确这一点后，`F=1` 不再是"凑出来的状态不变模型"，而是"参数为常量"的显式假设。

### 错位点 3：F=1 与 Q 取值语义不自洽

`F=1` 意味着模型认为 $\theta$ 不随 $k$ 漂移；按静态参数语义，`Q` 应当极小（接近 0），表示对"参数不变"假设的高置信。当前 `Q=1e-4` 偏大，相当于承认 $\theta$ 在递推过程中存在随机游走，与"静态参数"假设自相矛盾。

实际"质心偏置随窗口宽度变化"的部分属于观测噪声，应进入 `R` 而非 `Q`。修正方向：

- `Q` 减小到 $10^{-6}$ 量级，表达"参数静态"假设 —— **`Q` 取值属 config 字段 `kalman_q`，不在 step6 目录，本方案仅在文档给出建议值，代码改动另行处理**
- `R` 按窗口宽度自适应：小窗口 $R$ 小（精细观测），大窗口 $R$ 大（粗略观测）—— **此进阶方案可在 step6.cu 内实现，见修改 7**
- 若不实现自适应 `R`，至少保证 $Q/R$ 比例远小于当前值，让滤波器主要信任观测而非过程漂移

### 错位点 4：观测噪声模型缺失

当前 `R=2e-3` 是全局常数，但不同窗口宽度的质心估计方差差异显著：

- 小窗口（`radius` 小）：质心接近 anchor，方差小，应配小 $R$
- 大窗口（`radius` 大）：质心受副峰与边界效应影响，方差大，应配大 $R$

等权 `R` 让 Kalman 把粗略观测与精细观测同等对待，削弱了精细观测的权重。修正方向：

1. **简单方案**：固定 `R`，但配合修改 4 的反向序列（先粗后细），让最后若干步精细节点不被前期粗节点拖偏 —— **此方案已在 step6.cu 内由修改 4 承担**
2. **进阶方案**：实现 $R[k]$ 自适应，例如 $R_k = R_0 \cdot (1 + \alpha \cdot k)$，让大窗口观测噪声随窗口宽度线性增长 —— **此方案可在 step6.cu 内实现，见修改 7**

### 错位点 5：跨端 truth 公式不一致（不在本次修改范围）

C++ 端 [step6.cu](file:///c:\Users\Lenovo\Desktop\ZKX\Task2\task2_gpu_cpu\step6\step6.cu) `prepare_step6_host_inputs` 已按 $\theta = (\text{delay} + 0.5(N-1) + \tau_{\text{filter}} + \tau_{\text{spline}})/(N-1)$ 计算 `state.truth`；Python 端 `Task2/task2_python/step6/step6.py` 仍是旧公式 $\theta = (0.5(N-1) + \text{delay})/(N-1)$，未含滤波与样条群延迟。

跨端 truth 不一致会破坏 Python/C++ 精度比对的物理含义。但 Python 端不在 step6 目录，**本次修改范围不含 Python；C++ 端 truth 公式已正确，无需改动**。Python 端 truth 补齐另行处理。

## 修改 1：观测权重加入高斯衰减

### 文件

[step6.cu](file:///c:\Users\Lenovo\Desktop\ZKX\Task2\task2_gpu_cpu\step6\step6.cu) `observations_from_feature_point` 函数内 `local_weight` 计算。

### 修改前

```cpp
for (int index = left; index <= right; ++index) {
    const double local_weight = std::max(0.0F, bundle[index]);
    weighted_index += local_weight * index;
    weight += local_weight;
}
```

### 修改后

```cpp
const double sigma = std::max(1.0, static_cast<double>(observation_count) / 8.0);
for (int index = left; index <= right; ++index) {
    const double offset = static_cast<double>(index - anchor);
    const double gaussian = std::exp(-offset * offset / (2.0 * sigma * sigma));
    const double local_weight =
        std::max(0.0F, bundle[index]) * gaussian;
    weighted_index += local_weight * index;
    weight += local_weight;
}
```

### 修改理由

当前质心权重 `max(0, bundle[i])` 在大 radius 时会把远处非负副峰拉入加权平均，使质心偏离主峰。加入高斯衰减后，远离 anchor 的特征贡献指数衰减，大 radius 窗口仍以主峰邻域为主，质心稳定。

## 修改 4：观测序列反向递推（从粗到细）

### 文件

[step6.cu](file:///c:\Users\Lenovo\Desktop\ZKX\Task2\task2_gpu_cpu\step6\step6.cu) `run_step6_impl` 函数内 `d_observations` 构造。

### 修改前

```cpp

    state.kalman_observations);
```

### 修改后

```cpp
std::vector<float> reversed_observations(state.kalman_observations.rbegin(),
                                         state.kalman_observations.rend());
auto d_observations = cusignal::DeviceArray<float>::from_host(
    reversed_observations);
```

### 修改理由

当前观测序列按 `radius=1..K` 顺序递推，先处理小窗口（精细局部质心），再处理大窗口（粗略全局质心）。Kalman 在前若干步收敛到精细位置后，被后期大窗口偏置观测拉偏。改为反向递推（`radius=K..1`），先处理粗略全局位置，再逐步收敛到精细局部位置，最后状态更接近真实目标。

### 注意

`F=1` 时状态预测模型为"状态不变"，反向递推在数学上等价于多尺度从粗到细估计，不破坏 Kalman 假设。若 `kalman_f != 1` 则不应使用此修改。

## 修改 7：在 step6.cu 中实现 R[k] 自适应（针对错位点 4 进阶方案）

### 修改理由

`radius` 小时窗口窄、质心接近 anchor、方差小，应配小 $R$；`radius` 大时窗口宽、质心受副峰与边界影响、方差大，应配大 $R$。等权 $R$ 让粗略观测与精细观测同等权重，削弱精细观测贡献。$R[k] = R_0(1 + \alpha k)$ 让大窗口观测噪声线性增长，Kalman 自动降低大窗口观测权重，与修改 4 的反向序列（先粗后细）配合后，最后若干精细观测主导收敛。

### 8.1 observations_from_feature_point 函数签名与内部命名

#### 修改前

```cpp
std::vector<float> observations_from_feature_point(
    const std::vector<float>& bundle, std::int64_t anchor, int observation_count)
{
    std::vector<float> observations;
    observations.reserve(observation_count);
    for (int radius = 1; radius <= observation_count; ++radius) {
        const int left = std::max(0, static_cast<int>(anchor) - radius);
        const int right = std::min(static_cast<int>(bundle.size()) - 1,
                                   static_cast<int>(anchor) + radius);
        double weighted_index = 0.0;
        double weight = 0.0;
        for (int index = left; index <= right; ++index) {
            const double local_weight = std::max(0.0F, bundle[index]);
            weighted_index += local_weight * index;
            weight += local_weight;
        }
        const double coordinate = weight > 0.0 ? weighted_index / weight : anchor;
        observations.push_back(static_cast<float>(coordinate / (bundle.size() - 1)));
    }
    return observations;
}
```

#### 修改后

```cpp
// 生成多尺度质心观测序列：radius=1..max_radius，每个观测是窗口内归一化加权质心。
// 观测索引 k 对应窗口宽度参数（非物理时间），作为对静态参数 theta 的序贯带噪观测。
std::vector<float> observations_from_feature_point(
    const std::vector<float>& feature_source,
    std::int64_t feature_peak_index,
    int max_radius)
{
    std::vector<float> multiscale_centroids;
    multiscale_centroids.reserve(max_radius);
    for (int radius = 1; radius <= max_radius; ++radius) {
        const int left = std::max(0, static_cast<int>(feature_peak_index) - radius);
        const int right = std::min(static_cast<int>(feature_source.size()) - 1,
                                   static_cast<int>(feature_peak_index) + radius);
        double weighted_index = 0.0;
        double weight = 0.0;
        for (int index = left; index <= right; ++index) {
            const double local_weight = std::max(0.0F, feature_source[index]);
            weighted_index += local_weight * index;
            weight += local_weight;
        }
        const double centroid_index =
            weight > 0.0 ? weighted_index / weight : feature_peak_index;
        multiscale_centroids.push_back(
            static_cast<float>(centroid_index / (feature_source.size() - 1)));
    }
    return multiscale_centroids;
}
```

#### 改名对照

| 修改前 | 修改后 | 理由 |
| --- | --- | --- |
| `bundle` | `feature_source` | "bundle"语义模糊；实际是特征来源（feature_bundle 或 correlation_feature），改名体现来源语义 |
| `anchor` | `feature_peak_index` | "anchor"过宽；实际是特征最强点的样本索引 |
| `observation_count` | `max_radius` | 实际语义是 `radius=1..K` 的最大半径 K，不是"观测样本数" |
| `observations` | `multiscale_centroids` | 每个元素是窗口内归一化加权质心，不是普通观测 |
| `coordinate` | `centroid_index` | 明确是质心位置索引 |
